PART 1 — 정책맵
================================================================

[P-01] 읽기 전용 원칙
허용: 폴더/파일 목록 조회, CLAUDE.md/README.md 내용 표시, 탐색기로 열기(위임)
금지: 이 앱에서 직접 파일 복사/이동/삭제/이름변경/내용 수정
강제: 파일시스템에 쓰기 작업이 필요하면 반드시 Windows 탐색기나 다른 도구로
      위임한다(double-click → os.startfile)
(유래: D-001)

[P-02] SSOT 루트 목록은 코드에 하드코딩, 설정 파일로 안 뺌
허용: main.py 상단 ROOTS 리스트를 직접 수정해서 루트 추가/삭제
금지: 없음(지금 규모에서 별도 config.json/yaml은 과한 추상화로 판단)
강제: 새 루트 추가 시 ROOTS 리스트 + Local_APP\CLAUDE.md 인덱스 표 둘 다 갱신
(유래: 이 프로젝트 README.md "새 SSOT 루트 추가 시" 절)

[P-03] 대상 폴더 판별 기준은 파일명(claude.md/readme.md)만, 내용 파싱 안 함
허용: 존재 여부로만 "인덱싱 대상" 판정
금지: CLAUDE.md 안 내용을 파싱해서 추가 로직(예: 오픈조건 자동 평가)을
      만드는 것 — MVP 범위 밖
(유래: D-004)

[P-04] 구조화 데이터는 "단순 목록"에만, 서술형 내용은 계속 텍스트가 SSOT
허용: 루트 경로처럼 순수 목록 성격 데이터는 JSON 레지스트리(ssot-roots.json)로
      관리하고 앱이 UI로 직접 갱신
금지: CLAUDE.md/README.md 안의 서술형 내용(결정이력/오픈조건/정책 등)을 구조화
      DB로 이관하는 것 — 텍스트가 아닌 별도 저장소가 "진실"이 되면 Claude Code
      세션 중 사람이 md를 직접 고칠 때 앱 데이터와 어긋나는 이중관리가 재발함
강제: 새로운 "단순 목록형" 데이터가 더 생기면 그때마다 이 판단(목록이냐 서술형
      이냐)을 다시 적용해서 구조화할지 결정
(유래: D-006)

[P-05] CLAUDE.md(init)는 레지스트리 산출물, 손 편집 금지(P-04 완화)
허용: 레지스트리(referenceCondition) 수정 → "동기화" 버튼으로 CLAUDE.md 재생성
금지: init CLAUDE.md를 직접 손으로 고치는 것(다음 동기화 때 덮어써짐, 파일에
      명시돼 있음)
강제: 동기화 전 기존 CLAUDE.md에 동기화 마커가 없으면 반드시 확인창을 띄운다
      (손으로 쓴 기존 내용을 실수로 덮어쓰지 않기 위함)
(유래: D-010 — P-04 "구조화 데이터는 단순 목록에만" 원칙을 이 앱 한정으로
완화. 재생성 가능한 산출물 구조라 이중관리 위험이 재발하지 않는다는 게 근거)
